# 거리 단음 실험 (`feature/distance-tone`)

Sense 카메라+두 ToF 통합 브랜치에서 분기했다. 기존 카메라/YOLOX와 두 센서 펌웨어는 유지한다.
새 앱 0.8.1-tone(versionCode 13)의 **개발자 모드 → 좌우 거리 → 거리 단음 테스트 켜기**로 사용한다.
기본은 꺼짐이다. 이번 변경 때문에 ESP32 펌웨어를 다시 올릴 필요는 없지만,
실제 거리 JSON을 보내는 `ThirdEyeSenseUsb` 펌웨어가 필요하다. 예전 PC용 거리 격자 출력은 지원 입력이 아니다.

## 소리 규칙

- 좌우 중 가까운 유효 USB 거리 한 개를 사용한다. 한 센서만 유효해도 그 값으로 울린다.
- 양쪽 귀에 같은 **880Hz 단음, 길이60ms**. 음높이는 바꾸지 않는다. 시작/끝5ms는 음량을 완만히 바꿔 클릭을 줄인다.
- 20cm 이하: 시작 간격180ms, 앱 상대 게인0.55.
- 4m: 시작 간격1200ms, 앱 상대 게인0.12.
- 사이는 선형 보간한다. 스케줄러 확인 주기는30ms여서 실제 간격에는 오차가 있다.
- 게인은 휴대폰 미디어 음량에 곱해지는 상대값이며 체감 음량 백분율/dB가 아니다. 시스템 음량을 강제로 바꾸지 않는다.
- 0/음수/null, 4m 초과, 마지막 센서값이1.5초보다 오래된 경우 무음이다. 영상만 계속 와도 센서 유효시간은 연장되지 않는다.
- Mock 데이터는 소리를 발생시키지 않는다. USB 외 모드에서 켤 수 없다.
- USB 재연결/모드 전환/개발자 화면 이탈/백그라운드/회전 때 테스트를 끈다. 돌아오면 직접 다시 켠다.
- 오디오 포커스를 얻지 못하거나 잃으면 중지한다. 다른 앱 오디오 종료 후에도 자동 재생하지 않는다.
- 현재는 방향, 공간음향, 접근 속도나 위험도를 표현하지 않는다. 물체 인식 결과와 거리도 융합하지 않는다.

## 실기기 확인

1. 앱 설치 후 미디어 음량을 낮게 설정한다. 보안 경고/실행 차단은 이 변경과 별도이며 해결됐다고 가정하지 않는다.
2. 휴대폰에 XIAO를 연결하고 Third Eye → 개발자 모드에서 USB 권한을 허용한다.
3. 좌우에 실제 거리값이 표시되는 것을 확인한다.
4. 좌우 거리 구역의 **거리 단음 테스트 켜기**를 누른다.
5. 판을 1m, 50cm, 20cm로 가까이 가져오며 간격이 짧아지고 음량이 커지는지 확인한다.
6. 두 센서 모두 유효 범위 밖/유효 표적 없음이면 멈추는지 확인한다. 한 센서만 가린 경우 다른 유효 센서값으로 울릴 수 있다.
7. USB 분리 시 정지, 영상만 들어오고 거리 패킷이 중단되면1.5초 이후 정지하는지 확인한다.
8. 끄기 버튼/사용자 화면으로 돌아가기/홈/화면 회전/휴대폰 카메라·Mock 전환 때 정지하는지 확인한다.
9. 다른 오디오에 포커스를 빼앗겼을 때 중지 문구가 표시되고 직접 켜야 재개되는지 확인한다.

## 검증 범위

`assembleDebug testDebugUnitTest lintDebug`로 Android 빌드와 기존 테스트 및 거리→간격/게인 정책 테스트를 실행한다.
정책 테스트는 전체 거리 범위의 단조성, 경계/상한, 한 센서 유효, 잘못된 값과 오래된 값의 무음을 확인한다.
AudioTrack 실제 소리, 음량 체감, 오디오 포커스, 이어폰·스피커·USB와의 동시 동작은 실기기 확인이 필요하다.
이 기능은 개발용 거리 표현 실험이며 보행 안전성을 검증한 기능이 아니다.

클라우드 검증 결과: APK 빌드 성공, 단위 테스트23개(실패/오류/건너뜀0), Lint 오류0·기존 경고7.
APK 서명 검증도 통과했다. 실제 단음 재생과 Galaxy 보안 차단 해제는 확인하지 않았다.
설치 파일은 이 브랜치의 `downloads/ThirdEye-0.8.1-tone-debug.apk`다.
