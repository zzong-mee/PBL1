# 거리 단음·HRTF 출력 확인

## 0.11.3: 미디어 음량과 출력 경로 사용

거리 단음, 가상 HRTF, 8×8 방향음, 레이더 스캔의 AudioAttributes usage를
`USAGE_ASSISTANCE_SONIFICATION`에서 `USAGE_MEDIA`로 변경했다.
이전 설정은 Android API 35 프레임워크 테스트에서 `STREAM_SYSTEM`으로 분류됐다.
UI는 미디어 음량을 안내했으므로 사용자가 조절하는 음량과 실제 실험 음향의 음량 분류가 달랐다.
시스템 음량이 낮거나 기기의 효과음 출력 정책이 다른 경우 영향을 받을 수 있었다.

수정 후에는 네 음향 컨트롤러가 `STREAM_MUSIC`으로 분류되는 것을 테스트한다.
개발자 화면의 물리 볼륨 키도 미디어 음량을 조절하게 했다. 시스템의 실제 음량이나
Bluetooth 연결 장치, 모노 설정은 앱이 임의로 바꾸지 않는다.

이 테스트는 Android 프레임워크 시뮬레이션이다. 특정 Galaxy에서 기존 무음의 직접 원인이
이 설정이었다거나, 버즈의 실제 출력과 HRTF 방향 구별이 수정 후 해결됐다는 실기기 검증은 아니다.

검증: 변경 전 `STREAM_MUSIC` 기대값 3과 실제 `STREAM_SYSTEM` 값 1의 불일치를 재현했다.
변경 후 네 컨트롤러의 미디어 음량 분류와 개발자 화면 볼륨 키 대상을 확인했다.
`assembleDebug testDebugUnitTest lintDebug` 성공, 테스트 50개 실패·오류·건너뜀 0,
APK 서명 검증 통과. 기존 HRIR 좌우 도달 시간·에너지·채널 순서 검사도 포함한다.

## 재시험

1. `ThirdEye-0.11.3-scan-debug.apk`로 앱을 업데이트한다. 펌웨어 변경은 없다.
2. 미디어 출력이 버즈인지 확인하고 두 이어버드를 착용한다. 음량은 낮게 시작한다.
3. Galaxy 접근성의 청각 보조에서 모노 오디오를 끈다. Galaxy Wearable의 360 오디오와
   추가 공간음향 효과도 비교 시험 중에는 끈다.
4. HRTF 가상 테스트의 `왼쪽`, `오른쪽`부터 비교한다. USB 센서 없이도 시험할 수 있다.
   버튼을 누를 때 읽는 이름은 중앙에서 들리는 TTS이며, HRTF 실험음은 별도의 짧은 광대역 펄스다.
   좌우 구별을 확인한 뒤 앞뒤를 비교한다. 개인 HRTF가 아니므로 앞뒤 외재화·구별은 별도 평가한다.
5. 실제 USB 거리값을 수신한 상태에서 `거리 단음 테스트 켜기`를 누른다.
   이 기능은 방향 없는 880Hz 단음이며 거리에 따라 음량과 반복 간격이 달라진다.

## 상태에 따른 구분

| 표시 | 의미와 다음 확인 |
| --- | --- |
| 유효한 4미터 이내 센서값 대기 | 재생에 쓸 최근 센서값이 없다. USB 연결·거리 갱신·측정 범위를 확인한다. |
| 가까울수록 빠르고 크게 재생 중 | 앱의 재생 호출은 성공했다. 실제 출력 장치·음량·음향 정책을 확인한다. |
| 다른 오디오 사용으로 중지됨 | 오디오 포커스가 바뀌었다. 다른 재생을 정리한 뒤 다시 켠다. |
| 오디오 재생 실패 | AudioTrack 초기화/쓰기/재생 오류다. `ThirdEyeAudio` 로그의 실제 예외를 확인한다. |

앱이 재생 중이라고 표시하는 것만으로 실제 이어폰에서 들렸다는 사실이 확인되는 것은 아니다.
휴대폰 스피커는 이어폰용 HRTF의 좌우 채널을 각 귀에 독립적으로 전달하지 못하므로 방향 시험에 쓰지 않는다.
