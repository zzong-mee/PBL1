# 1초 좌→우 청각 스캔

`feature/radar-scan`, 앱0.11.0-scan(18).
8×8 원본 전송 펌웨어와 A/B 장착·격자 보정은 기존과 동일하다. 펌웨어가 이미8×8이라면 앱만 업데이트한다.

## 사용

1. 개발자 모드 → **8×8 센서 방향 음향**에서 A/B 격자와 장착 확인을 먼저 한다.
2. 같은 카드 아래 **1초 좌→우 청각 스캔**에서 스캔당 최대 소리 방향 수를 고른다.
3. 기본3개로 시작하고1개/5개/전체16구간과 비교한다. 설정 변경은 다음1초 주기부터 적용된다.
4. **1초 좌→우 스캔 켜기**를 누른다. 기존 한 점 반복 방향음과는 별도 모드다.
5. ‘이번 주기 선택/현재까지 재생’ 숫자를 확인한다. 오래된 값이나 렌더링/스케줄 지연으로 실제 재생 수는 선택 수보다 적을 수 있다.
6. 정지는 같은 버튼을 다시 누른다. 다른 소리 모드 시작/모드 전환/보정 변경/화면 이탈/오디오 포커스 상실 때도 정지한다.

센서별64존이 없는 옛 펌웨어·장착 미확인 상태에서는 실제 스캔 방향음을 만들지 않는다.
스테레오 이어폰을 쓰고 시스템 추가 공간음향/모노를 끈 상태에서 낮은 음량부터 비교한다.

## 스캔 규칙

사용자 각도 표기는 **왼쪽 끝90° → 정면45° → 오른쪽 끝0°**다.
내부 HRTF 방위각은 +45° → 0° → -45°이며 서로 다른 표기임에 주의한다.
전방90°를16개 가로 구간으로 나눠 한 주기를1000ms로 고정한다. 한 구간은62.5ms이고
Android 예약 시각은 정수ms이므로62/63ms를 번갈아 사용한다. 초기200ms 준비 후 고정 시간축으로 반복한다.
빈 구간을 건너뛰어 시간을 압축하지 않고, 선택되지 않은 구간도 같은 시간만큼 무음으로 남긴다.

각 구간에서는 유효한 측정점 중 가까운 한 점을 후보로 사용한다. 같은 방위의 높이 후보가 여러 개라면 가까운 것을
고르고 그 존의 고도도 HRTF에 반영한다. 한 세로 열의 모든 높이를 각각 울리지는 않는다.

주기 시작 시3/5개 제한에서는 왼쪽·정면·오른쪽의30° 영역별 가까운 후보를 우선한다.
그 다음 가까운 후보로 남는 자리를 채우되, 이미 선택한 후보와 방위가15° 미만이면 건너뛴다.
1개 제한에서는 전체에서 가장 가까운 후보를 고른다.
최대1/3/5개 중 고를 수 있고, 전체16구간 모드는 간격 제한 없이 비교한다.
이 제한은 **방향 슬롯 수**이며 물체 개수가 아니다. 같은 벽이 여러 방향에서 울릴 수 있다.
표면 분할·사물 추적·위험도 판단은 아직 하지 않는다. 공간이 조밀하면 목표 개수보다 적게 선택될 수 있다.

선택 방향 슬롯은 한 주기 안에서 유지하되, 재생 직전에는 해당 구간의 최신 유효 측정점을 다시 고른다.
그래서 주기 시작 때의 오른쪽 값이1초 내내 신선한 것처럼 재생하지 않는다. 새 데이터가 없으면 무음이다.
기존 센서값 유효시간1초를 유지한다. USB 영상만 계속 들어와도 거리 유효시간은 연장되지 않는다.
최신 프레임에서 물체가 다른 구간으로 옮겨갔다면 새 구간 선택은 다음 주기까지 기다릴 수 있다.

## 소리

20ms Hann 광대역 소스 +512탭 HRIR 꼬리를 모두 포함해 약31.6ms의 스테레오 펄스로 만든다.
62.5ms 구간에 맞추기 위해 기존60ms 펄스를 단순히 잘라버리지 않는다. 실측 필터의 귀간 지연과 꼬리를 보존한다.
HRTF는 선택한 존의 방위/고도에 가까운 MIT KEMAR 실측 필터이며 단순 패닝이 아니다.
여기서 거리는 기존 연속 거리→게인 곡선(20cm 이하0.55,4m0.12,중간 선형)으로 **음량만** 바꾼다.
거리에 따른 반복 간격은 적용하지 않는다. 방향 방문 주기는 항상1초이므로 개별 방향의 재방문도1초다.
같은 필터는 캐시하며 단일 작업 스레드에서 미리 렌더링한다. 준비 안 된 구간은 밀어 재생하지 않고 무음 처리한다.
늦은 콜백도 과거 구간을 한꺼번에 재생하지 않는다(현재 구간에서20ms 넘게 늦으면 건너뜀).

## 한계

1000ms는 앱의 논리 예약 시간이다. 일반 Android Handler/AudioTrack과 Bluetooth는 하드 실시간이 아니므로
실제 귀에 도달하는 시간에는 지터·출력 지연이 있다. 특히 버즈의 전달 지연은 별도다.
현재 센서 전송은 약500ms마다여서1초 스캔이라고 정보 갱신이62.5ms마다 되는 것은 아니다.
같은 방향의 새 장애물은 다음 스캔 방문까지 최대약1초 기다릴 수 있으므로 즉각적인 충돌 경보로 검증된 기능이 아니다.
무음은 유효 측정값 부재이지, 장애물 없음의 보장이 아니다.

명목 FoV/장착각/격자 보정과 HRTF 측정 간격의 한계는 docs/tof-grid-direction.md를 따른다.


## 설치 없이 소리 예시 비교

`downloads/ThirdEye-radar-three-virtual-points.wav`는 실제 앱의 정책/렌더러를 JVM에서 실행해 만든
4초 길이 예시다. **가상** +30°/0.5m,0°/1.5m,-30°/3m의 세 점을1초마다 순서대로 훑는다.
사용자 각도 표기로는75°/45°/15°이며, 각각125ms/500ms/813ms 부근에서 짧은 소리가 난다.
실측 센서 녹음이 아니며 Android/Bluetooth 지연을 포함하지 않는다. 실제 코드로 생성한 스테레오 파형/정책 비교용이다.
도구 `tools/ExportRadarPreview.java`는 빌드된 Kotlin 클래스와 kotlin-stdlib를 classpath에 넣어 실행한다.

## 검증 결과

### 0.11.1 개발자 화면 종료 수정

격자 회전 Spinner의 `apply` 블록에서 한정하지 않은 `findViewById`가 Activity 대신 Spinner 내부를
검색했다. 화면 진입 때 자동 발생하는 첫 선택 콜백에서 형제 뷰인 장착 확인 CheckBox를 찾지 못해
`NullPointerException`으로 종료됐다. Activity를 명시해 확인란을 검색하도록 수정했다.
Robolectric API 35의 실제 레이아웃/Activity 수명주기 테스트에서 수정 전 동일 예외를 재현했다.
화면 진입·종료와 A/B 회전 변경 시 장착 확인 해제를 회귀 테스트에 추가했다.
이 테스트는 JVM Android 프레임워크 시뮬레이션이며 Galaxy 실기기 또는 실제 오디오 재생 검증은 아니다.
`downloads/ThirdEye-0.11.1-scan-debug.apk`로 기존 앱을 업데이트한다. 펌웨어 변경은 없다.
수정 후 `assembleDebug testDebugUnitTest lintDebug` 성공, 테스트49개 모두 통과, Lint 오류0·경고8
(기존7개와 Robolectric 최신 버전 안내1개),
APK 서명 검증 통과. 실제 휴대폰에서의 화면 진입·오디오 동작은 사용자 확인이 필요하다.

### 0.11.0 스캔 구현 당시

Android `assembleDebug testDebugUnitTest lintDebug` 성공. 단위 테스트47개, 실패/오류/건너뜀0.
Lint 오류0·기존 경고7. 새 테스트는 스캔 시간/각도,빈 구간 시간 유지,개수 제한,좌중우 우선·실제각도 간격,
구간별 최근접 선택,최신값 재확인,만료/지연 구간 생략,짧은 실측 HRTF의 길이/스테레오/클리핑을 검증한다.
APK 서명 검증 통과. 예시WAV는4주기/주기당3펄스/스테레오/클리핑 없음을 수치 확인했다.
Android AudioTrack 실제 재생·버즈 지연·방향 지각·다중점 구별은 실기기 검증 전이다.
