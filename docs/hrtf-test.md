# HRTF 실측 필터 방향 테스트

브랜치 `feature/hrtf-test`, 앱 **0.9.0-hrtf (versionCode 15)**.
단순 좌우 볼륨 조절이 아니라 MIT KEMAR의 양 귀 HRIR과 광대역 소리의 FIR 컨볼루션을 사용한다.
기존 카메라/센서/거리 단음은 유지하고 **개발자 모드 → HRTF 가상 방향 테스트**를 추가했다.

## 먼저 듣기

앱 설치 없이 `downloads/ThirdEye-HRTF-8-directions.wav`를 스테레오 이어폰으로 들어도 된다.
앱의 실제 Kotlin 렌더러가 만든 소리를 Java 도구로 내보낸14.4초 WAV다. 가상 거리2m의 간격/게인 규칙을 적용했다.
각 방향1.8초씩, 순서는 **앞 → 왼쪽 앞 → 왼쪽 → 왼쪽 뒤 → 뒤 → 오른쪽 뒤 → 오른쪽 → 오른쪽 앞**이다.
자동 재생 테스트와 같은 방향 순서이며 방향별 비교용이다. 중간 각도를 연속 보간하는 회전음은 아니다.

## 앱 사용법

1. `downloads/ThirdEye-0.9.0-hrtf-debug.apk` 설치. 기존 Galaxy 보안 경고가 해소된다고 보장하지 않는다.
2. 스테레오 이어폰을 연결하고 휴대폰 미디어 음량을 낮게 설정한다. 방향 비교에는 유선 이어폰을 권한다.
3. 휴대폰의 모노 오디오 및 Dolby/추가 공간음향 효과를 끄고 비교한다. 이중 공간화는 단서를 바꿀 수 있다.
4. Third Eye → 개발자 모드에서 아래 **HRTF 가상 방향 테스트**까지 스크롤한다.
5. 준비 완료 후 앞/뒤/좌/우 및 대각선 버튼으로 짧은 광대역 소리를 반복 재생한다.
6. **수평360도·8방향 순서 재생**은1.8초마다 다음 방향으로 바꾼다. **HRTF 정지**로 멈춘다.
7. 가상 거리 슬라이더(20cm~4m)를 움직이면 기존 연속 거리 정책에 따라 간격과 상대 게인이 바뀐다.
8. 앱을 벗어나거나 화면 회전/오디오 포커스 상실 시 정지한다. 돌아와도 자동 재생하지 않는다.

USB/센서/YOLO/인터넷 없이 HRTF 테스트를 사용할 수 있다. USB가 연결돼 있다면 기존 카메라·센서 표시도 유지한다.
거리 단음을 켜면 HRTF를 끄고, HRTF를 켜면 거리 단음을 끈다. 한국어 음성 테스트도 양쪽 소리를 멈춘다.
일반 버튼의 터치 TTS/햅틱 피드백은 유지한다. 최초 버튼 이름 안내가 끝난 뒤 반복되는 테스트음을 비교한다.

## 데이터와 구현

- 실측 데이터: MIT KEMAR normal pinna, Bill Gardner / Keith Martin, MIT Media Laboratory.
- 출처·재배포 조건·원본 및 추출본 해시는 assets/hrtf/PROVENANCE.txt와 MIT_KEMAR_LICENSE.txt에 포함한다.
  저자 인용 조건을 앱 화면과 이 문서에도 명시한다. 이것을 일반 MIT 소프트웨어 라이선스로 부르지 않는다.
- SOFA: 높이0도, 측정 반경1.4m, 방위0/45/90/135/180/225/270/315도, 샘플레이트44100Hz.
- SOFA 좌표는0=앞, +90=왼쪽, 180=뒤, 270=오른쪽이다. 수신기0=왼쪽 귀,1=오른쪽 귀.
- full HRIR512탭을 그대로 보존한다. 원본 Data.Delay=0 확인. 귀별 시간 정렬이나 개별 게인 정규화를 하지 않는다.
- 60ms 고정 시드 광대역 잡음에 Hann 포락선을 적용한 후, 각 귀 HRIR과 각각 FIR 컨볼루션한다.
- 모든 방향/귀에 **단일 공통 게인**을 적용해 PCM peak를0.6 이하로 두므로 실측 귀간/방향간 레벨차를 보존한다.
  재생 때 별도로 가상 거리 게인을 곱하고 시스템 미디어 음량을 강제로 변경하지 않는다.
- 계산은 단일 백그라운드 작업에서 한 번 수행하고 방향별 스테레오 PCM 버퍼를 준비한다.
  AudioTrack 44100Hz PCM16 stereo로 재생하며 매 반복마다 컨볼루션하지 않는다.
- 데이터 파싱/렌더링 실패 시 오류를 표시한다. 단순 패닝/모노로 조용히 대체하지 않는다.
- 추출: `tools/extract_hrtf.py input.sofa output.bin` (numpy/h5py 필요).
  WAV 출력: `tools/ExportHrtfPreview.java`, 빌드한 Kotlin 클래스와 kotlin-stdlib를 classpath에 넣어 실행.

## 실제 확인해야 할 것

이어폰 좌우 착용/모노 설정을 먼저 확인한 후, 눈을 감고 다른 사람이 방향 버튼을 골라
인지한 방향을 기록한다. 특히 앞↔뒤 혼동률을 확인한다. 버튼을 보고 예상한 것과 실제 청각 구별은 다르다.
개인 HRTF가 아니므로 누구나 앞뒤를 명확히 구별하거나 머리 밖에 소리가 느껴진다고 보장할 수 없다.
스피커는 귀 사이 누설이 생겨 이어폰 비교와 다르다. Bluetooth 지연도 측정하지 않았다.

이번 구현은 **수평8방향, 가상 음원 한 개**다. 높이, 중간 각도 필터 보간, 머리 추적,
세계 좌표 고정, 여러 동시 음원 및 ToF 존/표면 방향 연결은 아직 구현하지 않았다.
가상 거리 슬라이더는 반복 주기/게인만 바꾸며1.4m 실측 HRIR을 근거리 전파/반향 모델로 바꾸지는 않는다.
뒤쪽 테스트 소리는 실제 뒤쪽 장애물이 있다는 뜻이 아니다. YOLO는 이 테스트와 별개다.

## 검증 결과

- `assembleDebug testDebugUnitTest lintDebug`: 성공.
- 단위 테스트33개, 실패/오류/건너뜀0. Lint 오류0·기존 경고7.
- 실제 번들 HRIR 8방향·귀/탭/샘플레이트와 라이선스 파일 확인, 좌우 도달시간·에너지 방향 검사.
- FIR 임펄스 지연/채널 배치/꼬리 보존 검사, 실제8방향 출력의 구별·클리핑 없음·잘못된 입력 거부 검사.
- APK 서명 검증 통과. WAV를 앱의 동일 렌더러에서 출력하고 스테레오/길이14.4초/클리핑 없음/귀간 에너지차 확인.
- 클라우드에서 Android 기기 재생/사용자의 방향 지각은 확인하지 못했다. 빌드·수치 검증과 실청 검증을 구분한다.
