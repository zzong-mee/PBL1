# 8×8 존별 거리 → 추정 방위/고도 → 실측 HRTF

브랜치 `feature/tof-grid-direction`, 앱0.10.0-grid(17).
A=왼쪽, B=오른쪽이다. 센서별 최솟값에 고정 좌우 소리를 붙이는 방식이 아니다.
각 센서의64존 원본, 유효 상태, 읽기 이후 경과시간을 보존하고, 선택한 존의 방향을 계산한다.
YOLO와는 연결하지 않는다.

## 장착과 보정

사용자가 제안한 배치를 기준으로 A yaw=+22.5°(왼쪽), B yaw=-22.5°(오른쪽), pitch=0°로 설정했다.
센서의 **수평** 시야가45°라는 명목 모델에서 전방90°를 대상으로 한다. 실제 장착 확인 완료를 뜻하지 않는다.
실제 렌즈 시야 경계/광학 왜곡/장착 오차/두 시야 사이 빈틈과 중첩은 확인해야 한다.
렌즈와 센서의 가로세로 방향도 실제 확인해야 한다. 두 센서 원점의 위치 차이와 머리 중심의 위치 차이는
현재 모델에 포함하지 않으므로 근거리 위치 정확도를 보장하지 않는다.

1. 물체 하나를 각 센서 앞에서 좌/우, 위/아래로 움직인다.
2. 앱 **개발자 모드 → 8×8 센서 방향 음향**에서 A/B 격자를 본다.
3. A/B 각각 회전0/90/180/270° 및 좌우 반전을 조절한다.
4. 물체를 왼쪽으로 옮길 때 화면 왼쪽 칸, 위로 옮길 때 위쪽 칸이 반응하는지 확인한다.
5. 센서 A/B가 실제로 좌우22.5°·수평이고 격자 방향까지 맞을 때만 장착 확인 체크를 켠다.
6. **8×8 방향음 켜기**를 누른다. 장착 확인 없이는 시작하지 않는다. 회전/반전 변경 시 확인 체크와 소리를 해제한다.
7. 가상 HRTF 버튼/거리 단음/음성 테스트는 서로 겹쳐 재생하지 않는다.
8. 홈 이동, 화면 회전, 오디오 포커스 상실 때 정지하며 자동 재개하지 않는다. 보정 설정은 현재 세션용이다.

다른 장착각이라면 확인 체크로 우회하지 않는다. 현재 화면은 제안한22.5° 배치용이며 다른 yaw/pitch 입력 UI는 없다.

## 반드시 펌웨어도 업데이트

새 앱은 기존 스칼라 거리값만으로 방향을 만들지 않는다. 새 브랜치의
`firmware/ThirdEyeSenseUsb/ThirdEyeSenseUsb.ino`와 **GeyePacket.h, TofGridJson.h**를 같은 폴더에 둔다.
기존 XIAO_ESP32S3 / USB CDC Enabled / PSRAM OPI 설정으로 업로드한다. 물리 배선은 유지한다.
센서는 이번 펌웨어부터 **8×8·5Hz**이며 데이터 전송 목표는 약500ms마다다. 실제 속도/지연은 실측이 필요하다.

종류1 GEYE JSON에는 이전 left_mm/right_mm과 함께 다음 필드가 들어간다.

- grid_size=8, grid_order="st_uld_raw"
- left_zones_mm/right_zones_mm: **정확히64개**의 거리 또는null. 무효 칸을 삭제하지 않는다.
- left_status/right_status:64개의 ST target_status. 오래된/실패한 센서는null.
- left_age_ms/right_age_ms: get_ranging_data로 읽은 후의 경과시간. 내부 적분·전송 지연을 모두 나타내는 값은 아니다.
- tof_error: 센서 오류 원인. 센서 실패 시 방향음을 생성하지 않는다.

각 존의 첫 번째 표적만 사용하며 상태5/6/9, 표적 수>0, 거리1~4000mm를 유효로 인정한다.
1초 이상 지난 값/센서 실패는 전체 칸null로 전송한다. 양 센서는 하드웨어 동기 측정이 아니다.
패킷 버퍼4096바이트를 넘으면 잘린 격자를 보내지 않는다. JPEG와 거리 패킷 분리는 유지한다.
이전 펌웨어면 좌우 거리/영상은 보일 수 있어도 8×8 방향음은 데이터 대기 상태다.

## 방향 계산

회전/반전 보정 후 각 셀 중심의 시선 방향을 계산한다. 수평/수직 명목FoV45°의
rectilinear 모델을 사용하고, 센서 pitch/yaw를 회전 적용한다. 이는 ST 광학 보정표를 적용한 정밀 계측 모델이 아니다.
짝수8×8이므로 중앙은 한 칸이 아닌4개 칸 사이이며, 각 칸에는 폭과 깊이 내 여러 반사체가 있을 수 있다.
8×8로부터 얻는 각도 정보는 명목상 한 칸 약5~6° 수준이며 표시 소수점이 물리 정확도를 의미하지 않는다.

양 센서의 유효 측정점 최대128개 중 가장 가까운 점을 초기 선택한다. 동률이면 정면에 가까운 점을 우선한다.
선택한 센서+존이 유효하면 다른 점이150mm 넘게 가까워져야 전환한다. 무효/오래된 값이면 즉시 재선택/무음이다.
선택한 센서·원본 존 번호·거리·추정 방위/고도를 화면에 표시한다.
**이는 사물/표면 추적이 아니다.** 같은 벽이 여러 칸을 차지하는 것과 단일 칸 잡음을 완전히 처리하지 않는다.
여러 물체가 있을 때 현재는 이 규칙으로 한 점만 들려준다. 위험도 판단/다중 음원은 아직 구현하지 않았다.

## HRTF 출력

MIT KEMAR의710개 실측 방향(높이 포함)을 새 `kemar-spatial.bin`에 포함했다.
출처/저자/사용 조건은 기존 assets/hrtf의MIT_KEMAR_LICENSE.txt와PROVENANCE.txt를 따른다.
원본SOFA의 전체512탭/귀간 시간차를 보존한다. tools/extract_spatial_hrtf.py로 고정 원본 해시를 확인해 추출한다.

선택한 존의 방위/고도와 구면상 가장 가까운 실측 HRTF를 고른다. 수평8개 방향에 고정 매핑하지 않는다.
MIT 데이터의 측정 간격은 방향/고도에 따라 다르다(예: 수평 약5°, 고도 약10°). 현재는 **최근접 필터**이며
연속 필터 보간은 하지 않는다. 추정 존 각도와 실제 사용되는 HRTF 각도가 일치한다고 보장하지 않는다.
필터 계산은 백그라운드에서 수행하며, 중간에 입력이 바뀌거나 만료/정지되면 오래된 렌더 결과를 버린다.
거리의 음량/간격은 지수 평활화(접근80ms/이격350ms)와 기존 연속 곡선으로 제어한다.
모든 방향/귀에 같은 FIR L1 상한 기반 정규화를 사용해 클리핑을 막고 귀간 레벨차를 보존한다.
보수적 정규화로 가상8방향 테스트와 출력 음량이 다를 수 있다. 시스템 미디어 음량은 강제 변경하지 않는다.

수평/높이 모두 개인 HRTF가 아닌 KEMAR 근사다. 실제 방향을 청각적으로 얼마나 구분하는지는 실기기 검증이 필요하다.
현재 센서가 관측하지 않은 뒤쪽 음원은 생성하지 않으며, 머리 추적/세계 좌표 고정도 없다.

## 검증

Android 빌드와 기존 테스트, 새64존 파서/광선 계산/회전·반전/시간 만료/존 선택/밀집 HRTF 테스트를 실행한다.
펌웨어 C++ writer의 실제 JSON fixture를 Android 파서가 읽어 마지막 존63까지 보존하는지도 확인한다.
C++ writer는 무효 셀, stale 센서, NB_TARGET_PER_ZONE stride, 버퍼 초과를 별도로 검사한다.
카메라/센서 통합의 ESP32 전체 컴파일과 새8×8 동작은 Windows에서 확인해야 한다.
클라우드의 Arduino 도구 다운로드 접근 제한은 여전히 남아 있다. 실기기 성공으로 표현하지 않는다.

이번 검증 결과: Android 빌드 성공, 단위 테스트39개(실패/오류/건너뜀0), Lint 오류0·기존 경고7.
C++ 격자 writer 테스트와 실제 ST2.1.0 헤더를 포함한 호스트 문법 검사도 통과했다(카메라/Arduino는 대역).
새8×8 펌웨어의 ESP32 대상 전체 빌드·실물 거리·방향 지각은 미검증이다. APK 서명 검증은 통과했다.
