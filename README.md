# Third Eye

## Sense 카메라와 YOLOX 통합 (`feature/sense-camera-yolox`)

**현재 앱: 0.8.0-sense · versionCode 12.** 기본 입력은 Sense USB 카메라다.
[통합 펌웨어와 Windows/Android 설치·테스트 안내](firmware/ThirdEyeSenseUsb/)를 따른다.
기존 두 센서 테스트는 사용자 실측 확인 완료이며, 새 카메라 통합은 실기기 확인이 필요하다.
아래의 휴대폰 카메라/단일 센서 설명은 이전 기반 버전 기록이다.

## 두 센서 실측 테스트 (`feature/dual-tof-sensors`)

새 펌웨어 [ThirdEyeDualTof](firmware/ThirdEyeDualTof/)는 기존 Y선 배선을 유지하며 부팅 때
A/B 주소를 분리해 두 거리 격자를 PC 시리얼 모니터에 출력한다. 기존 단일 센서 스케치는 보존한다.
**새 펌웨어의 ESP32 전체 컴파일과 실물 검증은 아직 필요하며, Android용 JSON 송신은 포함하지 않는다.**
설치·주소 표기·Windows 업로드·측정 절차와 검증 한계는 위 문서를 따른다.

**기반 앱 버전: 0.7.2-phone** · versionCode: 11

## 스마트폰 카메라 테스트 브랜치

`feature/phone-camera`에서는 외부 하드웨어 없이 휴대폰 후면 카메라로 중앙 물체를 인식한다.
Android 기본 Camera2 API로 0.1초 간격을 목표로 JPEG 촬영을 요청하고 기존 YOLOX-Nano로 분석한다. 추가 라이브러리는 없다.

1. Android Studio에서 Git → Fetch 후 `origin/feature/phone-camera`를 체크아웃한다.
2. Galaxy A34를 선택하고 Run한다. 기존 앱과 패키지가 같아 업데이트 설치된다.
3. 카메라 권한을 허용하고 렌즈를 물체에 향한 뒤 약간 기다려 **중앙 물체**를 누른다.
4. **일시정지** 또는 앱을 벗어나면 카메라를 해제한다. **다시 시작**으로 재개한다.
5. 권한을 영구 거부한 경우 휴대폰 설정 → 애플리케이션 → Third Eye → 권한에서 카메라를 허용한다.

사용자 화면과 터치·TTS·햅틱 조작은 유지한다. 개발자 모드 상단에서 실제 후면 카메라 분석 영상과 중앙의 노란 점을 확인할 수 있다. 노란 사각형은 중앙 탐색 영역, 초록 상자는 탐지 결과다. 촬영 요청은 0.1초 간격(목표 최대 10회/초)이며, 실제 촬영·분석 속도에 따라 화면이 갱신된다. 촬영이 늦으면 완료 후 다음 요청을 보내며, 분석 중 새 프레임은 대기열에 쌓지 않고 건너뛴다. USB 연결 버튼으로 기존 USB 테스트로 전환하고, 휴대폰 카메라 보기 버튼으로 돌아온다. 거리 수치는 카메라와 별개인 Mock/USB 값이다.
거리 측정·보행 위험 판단은 제공하지 않는다. 실제 Galaxy 카메라·회전·권한 거부·재개는 실기기 확인이 필요하다.
아래 내용은 기반 USB 버전의 기능 기록이다.


시각장애인을 위한 Android AI 보행 보조 앱. 현재 **사용자용 시작 화면과 별도의 개발자 화면**을 제공하는 개발 버전이다.
Mock 거리와 USB Serial JSON 수신은 개발자 모드에서 테스트한다.
외부 USB JPEG의 일반 사물 탐지·중앙 물체 안내를 추가했으며 실제 장치 통합은 검증 전이다.
거리 센서 실측·위험도 판단·자동 보행 안내는 아직 완성되지 않았다. 상세 범위는 [외부 카메라 개발 문서](docs/external-camera.md)를 참고한다.

## 개발 환경과 실행

- Android Studio의 AGP 8.11 지원 버전 이상 (예: Narwhal 2025.1.1 이상)
- JDK 17 이상 (클라우드 검증은 JDK 21), Gradle 8.13 Wrapper
- Android SDK Platform 36, Build Tools 35.0.0
- Kotlin 2.1.20, XML 기반 Android 기본 View, minSdk 26 / targetSdk 36
- ONNX Runtime Android 1.31.0: 번들 YOLOX-Nano 모델의 로컬 CPU 추론
- AndroidX Core 1.17.0: Android 버전별 안전한 BroadcastReceiver 등록에 사용. USB 전송은 Android 기본 Host API 사용
- JUnit 4.13.2는 단위 테스트, org.json 20260814는 Android 기본 JSON 파서의 JVM 테스트 대체 구현에만 사용

1. Android Studio에서 이 폴더를 열고 SDK 36을 설치한 뒤 Gradle Sync한다.
2. Galaxy A34의 개발자 옵션에서 USB 디버깅을 활성화하고 PC 연결을 승인한다.
3. `app` 실행 대상을 선택하고 Run한다. 앱 ID: `com.guideeye.app`.
4. 기기 TTS 설정에서 한국어 지원 엔진·한국어 음성 데이터를 준비하고 미디어 음량을 확인한다.
   TTS는 기기에 설치된 엔진을 사용한다. 엔진에 따라 음성 데이터 설치나 네트워크가 필요할 수 있다.

명령줄에서는 Android SDK 위치를 `ANDROID_HOME` 또는 로컬 `local.properties`의 `sdk.dir`로 지정한다.
`local.properties`는 Git에서 제외된다.

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
# 기기 연결 후 (PC에 adb 필요)
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## USB 거리 수신 테스트

앱 데이터 전송은 **USB 유선만** 사용한다. Android USB Host API로 Espressif(VID 0x303A)의
단일 CDC ACM 제어 interface와 단일 CDC data interface를 가진 장치 하나를 지원한다.
USB Serial 터미널 앱에서 통신이 된 사실만으로 모든 descriptor 구성이 지원된다고 보장하지 않는다.
여러 지원 장치를 동시에 연결하거나 다른 USB-UART 칩을 사용하는 장치는 이번 구현 범위 밖이다.

1. Mac에서 GitHub의 최신 `main`을 Pull하고 앱을 Galaxy A34에 다시 설치한다.
2. Serial USB Terminal 앱에서 Disconnect 후 앱을 종료해 USB interface를 해제한다.
3. XIAO에 `firmware/ThirdEyeUsbTest/ThirdEyeUsbTest.ino`를 업로드한다.
   보드 `XIAO_ESP32S3`, `USB CDC On Boot: Enabled`를 사용한다.
4. XIAO를 휴대폰에 USB로 연결하고 Third Eye 하단 **개발자 모드 → USB 연결 / 다시 연결**을 누른다.
5. USB 접근 권한을 허용한다. 좌측 **0.50미터**, 우측 **1.20미터**가 표시되어야 한다.
   이 값은 펌웨어의 고정 테스트 값이며 실제 센서 실측이 아니다.
6. 케이블 분리 시 분리 상태가 표시되고 거리 값이 지워지는지 확인한다.
7. 권한 거절 후 연결 버튼 재시도, 재연결, Mock 전환을 확인한다.
8. 앱을 백그라운드로 보내면 연결이 닫힌다. 복귀 후 연결 버튼을 다시 누른다.

115200 / 8N1, DTR·RTS 활성화를 요청한다. 수신은 worker thread, UI는 main thread에서 처리한다.
각 줄은 LF 또는 CRLF로 끝나는 JSON이어야 한다:

```json
{"left_mm":500,"right_mm":1200}
```

각 값은 1~100000mm 범위의 정수여야 하며, 두 값이 모두 유효한 경우만 갱신한다.
USB read 분할/병합을 처리하고 512바이트를 넘는 줄은 줄 끝까지 폐기한다.
잘못된 줄은 무시한다. 4초간 유효한 측정값이 없으면 연결을 닫고 이전 거리를 지운다.
오류/권한 거절 시 Mock으로 자동 전환하지 않는다. Mock 전환은 버튼으로 명시적으로 한다.
USB 연결 성공은 카메라 연결이나 실제 센서 측정 성공을 뜻하지 않는다.

후속 단계에서는 ESP32-S3가 I²C 센서 두 개를 읽도록 펌웨어를 추가하고,
JPEG 프레임 전송을 실제 보드와 검증한다.
YOLOX-Nano의 USB JPEG 추론을 추가했다. 실제 ToF 측정 연동, 센서 융합, 위험도/중복 음성 억제는 후속 단계다.

## 접근성 UI (0.3.0)

화면을 연결/모드, 좌우 거리, 음성 안내, 카메라 상태 구역으로 나누었다.
큰 글자, 대비가 높은 색상, 최소 64dp 버튼, TalkBack 제목 탐색을 적용했다.

- TalkBack 터치 탐색을 사용하지 않을 때: 활성화된 버튼에 손을 대면 버튼 이름을 한국어 TTS로 안내하고 터치 진동을 준다.
- 버튼 실행은 손을 뗄 때 `performClick()`으로 처리한다. 버튼에서 시작한 터치는 ScrollView가 가로채지 않는다. 버튼 밖으로 이동하면 취소 안내·진동을 주고, 다시 안으로 돌아와도 그 터치는 실행되지 않는다. 화면 스크롤은 버튼 밖의 글자나 빈 공간에서 시작한다.
- TalkBack 터치 탐색을 사용하면 별도의 이름 읽기/진동을 중복 실행하지 않고 TalkBack 기본 탐색과 두 번 탭 실행을 유지한다.
- 이름 읽기는 한국어 TTS 초기화 완료 후 가능하며, 진동은 기기의 터치 진동 설정을 따른다.
- 음성 테스트는 버튼 이름을 먼저 읽은 뒤 테스트 문구를 이어 읽는다. 새 버튼 터치는 이전 음성을 대체한다.
- UI 변경으로 USB/Mock 거리 수신 및 TTS 초기화 로직의 기능 범위를 확대하지 않았다.

실기기 확인: 손을 댄 채로 유지하면 실행되지 않는지, 손을 떼면 한 번 실행되는지,
버튼 밖 이동 시 취소되고 버튼 밖에서 스크롤이 가능한지, 이름 읽기와 진동이 동작하는지 확인한다.
TalkBack 켜기/끄기, 큰 글꼴, TTS 미준비/사용 불가 상태도 확인한다.
이 버전의 터치 음성·진동 및 화면 배치는 실기기에서 아직 검증하지 않았다.

### 0.3.1 취소 동작 수정

버튼에서 시작한 손가락 이동은 화면 스크롤로 전환하지 않는다.
버튼 밖으로 이동하면 “취소했습니다” 음성·진동을 한 번 주고, 손을 뗄 때까지 취소 상태를 유지한다.
다른 버튼 위에서 손을 떼도 그 버튼이 실행되지 않는다. 여러 손가락을 사용하면 원래 버튼 동작을 취소한다.
스크롤은 버튼 밖의 글자나 빈 공간에서 시작한다.
실기기에서 버튼 길게 유지 → 밖으로 이동 → 다시 안으로 이동 → 손 떼기(실행 없음),
정상 누르기/떼기(한 번 실행), 빈 공간 스크롤을 확인해야 한다.

## 사용자 화면 / 개발자 모드 (0.4.0)

앱의 기본 진입점 MainActivity는 스크롤 없는 사용자용 화면이다.
큰 **상태 듣기**, **사용 방법 듣기** 버튼을 제공하고 하단에 작은 **개발자 모드** 버튼을 고정한다.
개발자 버튼도 최소 48dp의 터치 영역과 이름 읽기·진동·취소 동작을 제공한다.
한국어 TTS가 준비되면 TalkBack 터치 탐색을 사용하지 않는 경우 처음 화면의 버튼 위치를 음성으로 안내한다.
가로 화면에서는 주요 버튼을 좌우로 배치한다.

보행 안내가 아직 구현되지 않았으므로 사용자 화면에서 사용 불가 상태를 명시한다.
상태/사용법 음성은 제공하지만 실제 보행 안내 시작 동작을 구현한 것처럼 표시하지 않는다.
사용자 화면은 Mock 갱신이나 USB 연결을 시작하지 않는다.

개발자 모드는 별도 DeveloperActivity로 분리했다.
기존 USB 연결·Mock·거리·음성 테스트·카메라 상태를 이곳에 유지한다.
상단 고정 **사용자 화면으로 돌아가기** 또는 시스템 뒤로가기로 돌아올 수 있다.
개발자 화면을 떠나면 USB와 Mock 갱신은 기존 lifecycle 규칙에 따라 중지된다.

기기 확인: 새로 앱 실행 → 사용자 화면 → 상태/사용법 음성 → 하단 개발자 모드 → USB/Mock 테스트 → 돌아가기.
손가락 밀어서 취소, TalkBack, 가로 회전, 큰 글꼴에서의 배치도 확인해야 한다.
이번 화면 전환과 배치는 실기기에서 아직 검증하지 않았다.

## 메인 버튼 구성 (0.5.0)

- **중앙 물체**: 카메라 화면 중앙의 사물 종류를 안내하기 위한 버튼이다.
  현재 카메라/객체 인식이 미구현이므로 확인할 수 없음을 음성으로 알린다. 가상의 사물 이름을 출력하지 않는다.
- **일시정지 / 다시 시작**: 손을 떼면 현재 음성 재생·대기열을 멈추고 일시정지 상태로 전환한다.
  버튼 이름과 화면 상태가 바뀌고, 다시 누르면 일시정지를 해제한다.
  재개 시 실제 인식이 시작됐다고 안내하지 않으며 인식 준비 중임을 알린다.
- 일시정지 중에도 버튼 이름·취소·상태 확인 응답은 제공한다. 중앙 물체를 누르면 일시정지 상태를 안내한다.
- 일시정지 상태는 화면 회전과 개발자 화면 왕복 시 유지한다. 앱의 새 세션에서는 초기화된다.
- 하단 개발자 모드와 기존 USB/Mock 테스트는 유지한다. 사용자 화면의 일시정지는 별도의 개발자 테스트를 제어하지 않는다.
- 실제 카메라 분석/자동 장애물 안내 파이프라인은 아직 없으므로 이를 중단·재개했다고 주장하지 않는다.
  향후 해당 기능을 연결할 때 이 일시정지 상태를 연동해야 한다.

업데이트 후 중앙 물체 준비 안내, 일시정지/재개 음성·버튼명, 일시정지 중 중앙 물체 응답,
회전/개발자 화면 왕복의 상태 유지, 터치 취소와 TalkBack 동작을 실기기에서 확인한다.

## 접근성 보완 (0.5.1)

- 메인은 중앙 물체 / 일시정지·다시 시작의 두 버튼과 하단 개발자 모드로 유지한다.
- 첫 음성 안내에 버튼 위치와 누르기·떼기·밖으로 밀어 취소하기를 포함한다.
  화면 회전으로 Activity가 재생성되어도 이미 시작한 설명을 자동으로 반복하지 않는다.
- TalkBack에는 버튼의 기능 설명과 현재 일시정지·음성 준비·인식 미구현 상태를 제공한다.
  TalkBack 터치 탐색 중 별도의 앱 이름 읽기와 터치 진동을 중복 실행하지 않는다.
- 음성 준비/오류 상태는 정중한 접근성 알림(live region)으로 전달한다.
- 일반 터치의 접촉/실행/취소에 플랫폼 선택/확인/거절 햅틱을 사용한다.
  Android 11 이상에서 CONFIRM/REJECT를 요청하며 구형 기기에서는 LONG_PRESS로 대체한다.
  기기의 진동 설정과 효과 지원 여부를 따르며 강제 진동 권한을 추가하지 않는다.
- 중앙 물체·일시정지·재개에 모양 아이콘을 더해 색에만 의존하지 않는다.
  글꼴 배율이 1.3을 넘거나 화면 높이가 480dp 미만이면 아이콘을 생략하여 글자 공간을 우선한다.
- 중복된 상단 상태 문구를 줄이고 메인 버튼의 공간을 확보한다.

실기기 확인 필요: TalkBack 기능/상태 읽기와 탐색 순서, 이름 음성과 TalkBack 중복 여부,
접촉/실행/취소 진동, 한국어 음성 미설치, 글꼴 확대와 가로 화면에서 버튼/하단 개발자 모드 노출.
실제 시각장애인 사용자에게 위치 탐색과 취소 방법의 이해·실수 빈도를 확인해야 하며,
자동 빌드·Lint·기존 단위 테스트 통과만으로 사용성이 검증된 것은 아니다.

## 외부 카메라 전환 (0.6.0)

사용자 요청에 따라 스마트폰 CameraX 대신 XIAO ESP32-S3 Sense의 USB JPEG를 입력으로 사용한다.
상세 설정·모델 라이선스·새 펌웨어 및 검증 한계는 [docs/external-camera.md](docs/external-camera.md)에 있다.
**이전 JSON 전용 펌웨어만으로는 영상이 전송되지 않는다.** 새 카메라 검증용 펌웨어는
거리 센서 배선 확인과 ESP32 빌드·실기기 검증이 남아 있다. 거리 실측 연동은 배선 사진 확인 후 진행한다.


## 실제 ToF 센서 테스트 브랜치

이 브랜치(feature/real-sensor-test-camera-base)는 feature/phone-camera를 기반으로 실제 VL53L8CX 거리센서 테스트를 추가한다. 스마트폰 카메라와 YOLOX-Nano 객체 인식 흐름은 유지하고, 거리 입력은 XIAO ESP32-S3 Sense에서 USB CDC로 받는다.

### 현재까지 구현한 내용

- Android USB 거리 수신 계층이 기존 `left_mm` / `right_mm` JSON을 계속 지원한다.
- 64존 원본을 보내는 `left_zones_mm` / `right_zones_mm` 배열 형식을 추가했다.
- 배열이 들어오면 앱은 각 배열의 가장 가까운 유효 거리(mm)를 좌우 대표 거리로 사용한다.
- JSON 줄은 USB read 경계와 관계없이 조립하며, 잘못된 값과 유효 범위를 벗어난 값은 무시한다.
- XIAO ESP32-S3 Sense용 VL53L8CX 단일 센서 테스트 펌웨어를 추가했다.
- 현재 펌웨어는 센서 A만 활성화하고 센서 B의 LP(D3)를 LOW로 유지한다.
- XIAO 배선은 SDA=D4, SCL=D5, 센서 A LP=D2, 센서 B LP=D3이다.
- Serial Monitor에서 거리값을 4×4 격자로 확인하고 `r` 입력으로 8×8로 전환할 수 있다.

펌웨어 파일은 [firmware/VL53L8CX_DistanceGrid_XIAO](firmware/VL53L8CX_DistanceGrid_XIAO/)에 있다. Arduino IDE에서 `XIAO_ESP32S3`, USB CDC On Boot 활성화, 포트 선택 후 업로드한다. Serial Monitor 속도는 115200이다.

### 현재 확인된 상태

- XIAO ESP32-S3에서 VL53L8CX 단일 센서 초기화와 거리값 출력이 확인됐다.
- 4×4 거리 격자 출력이 확인됐다.
- 센서 A와 B를 같은 I²C 주소로 동시에 켜는 구성은 아직 사용하지 않는다.
- 현재 펌웨어 출력은 사람이 읽는 거리 격자이며 Android 앱으로 보내는 JSON 송신은 다음 단계다.

### 다음 단계

1. 센서 B를 LP 순서 제어로 깨우고 I²C 주소를 변경한다.
2. 두 센서의 64존 데이터를 동시에 읽는다.
3. `left_zones_mm` / `right_zones_mm` JSON으로 USB CDC에 전송한다.
4. Android 개발자 화면에서 실제 좌우 센서값을 확인한다.
5. 센서값을 카메라 객체 인식, 위험도 판단, 공간음향 출력과 연결한다.

실제 센서값, 위험도 판단, 자동 보행 안내는 아직 실기기 검증 전이다.
